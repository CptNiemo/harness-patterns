## §2 Misuse pairs (DO correct — the distinction is exam-tested)

| If the user says… | PMI distinction | D |
|---|---|---|
| milestone (for work that takes days) | **milestone** = zero-duration significant point; **activity** has duration; **deliverable** = verifiable product; **work package** = lowest WBS level | D2 |
| risk (for something that already happened) | **risk** = uncertain future event → risk register; **issue** = has occurred → issue log | D1 |
| assumption ↔ constraint | **assumption** = believed true without proof; **constraint** = limiting factor imposed on the project | D1 |
| scope creep ↔ gold plating | **scope creep** = uncontrolled additions bypassing change control; **gold plating** = team adds unrequested extras | D1/D2 |
| plan (meaning the approved version) | **baseline** = approved version, changed only through change control | D2 |
| critical path (meaning "most important") | **critical path** = longest path, zero float; sets the minimum project duration | D2 |
| lead ↔ lag | **lead** = successor starts early (overlap); **lag** = imposed wait | D2 |
| effort ↔ duration | **effort** = person-hours; **duration** = calendar time | D2 |
| retrospective ↔ lessons learned | **retrospective** = per-iteration team event (agile); **lessons learned register** = cumulative project document | D3/D1 |
| sponsor ↔ stakeholder ↔ customer | **sponsor** funds and champions; **stakeholder** = anyone affected; **customer** accepts the product | D1 |
| project ↔ program ↔ portfolio ↔ operations | temporary + unique · related projects for shared benefits · grouped for strategy · ongoing repetitive work | D1 |
| progressive elaboration ↔ rolling wave ↔ creep | detail grows as information improves · near-term detailed, later high-level · uncontrolled scope | D2 |
| Definition of Done ↔ acceptance criteria | **DoD** = team-wide quality checklist for any increment; **acceptance criteria** = per-story conditions | D3/D4 |
| product backlog ↔ sprint backlog | **product backlog** = all work, product-owner-owned; **sprint backlog** = this sprint's commitment, team-owned | D3 |
| velocity ↔ throughput ↔ cycle time | points per sprint (Scrum) · items per unit time (Kanban) · start→finish per item | D3 |
| QA ↔ QC | **Manage Quality** = process, prevention; **Control Quality** = inspect deliverables | D2 |
| verification ↔ validation | **verification** = meets specification (built right); **validation** = meets the need (right thing built) | D4 |
| requirements gathering | PMI says **elicitation** — requirements are drawn out through techniques, not collected | D4 |
| contingency ↔ management reserve | **contingency** = known-unknowns, PM-controlled, inside the baseline; **management reserve** = unknown-unknowns, sponsor-controlled, outside it | D2 |
| change request ↔ change control ↔ configuration management | proposal · review/approve process (CCB) · version control of product artifacts | D1/D2 |
| resource (for a person) | PMBOK 7 says **team member**; "resource" = physical or team resources collectively | D1 |
| status meeting (for the daily scrum) | **daily scrum** = 15-min sync for the developers, not a report to the PM | D3 |
| MVP ↔ increment | **MVP** = smallest releasable product to learn from; **increment** = usable output of one iteration | D3/D4 |
| stakeholder register ↔ RACI | **register** = who + interest/influence/expectations; **RACI** = responsibility assignment matrix | D1 |
| estimate (meaning a promise) | **estimate** is probabilistic — analogous, parametric, bottom-up, three-point (PERT); a **commitment** is different | D2 |
| mitigation (for every risk response) | threats: **avoid / mitigate / transfer / accept / escalate**; opportunities: **exploit / enhance / share / accept / escalate** | D2 |
| data ↔ information ↔ reports | **work performance data** raw → **information** analysed → **reports** communicated | D1 |
| business case ↔ charter | **business case** = justification (why); **charter** = authorisation (formal start, PM named) | D1/D4 |
| functional ↔ non-functional requirement | what the solution does · how well it does it (performance, security, usability) | D4 |
| user story ↔ use case | "As a… I want… so that…" need statement · actor–system interaction scenario | D4 |
| shortcut (for adapting process) | **tailoring** = deliberate adaptation of approach, governance and processes to the project | D1 |
| budget (for EVM terms) | **PV** planned value · **EV** earned value (budgeted cost of work performed) · **AC** actual cost · **BAC** budget at completion | D2 |
| stakeholder management | PMBOK 7: **stakeholder engagement** — "managing" people was dropped | D1 |
| requirement (for a design decision) | **requirement** = condition/capability needed; **specification / design** = how it is satisfied | D4 |

## §3 Domain term pools (nudge + quiz source)

**D1 · Fundamentals (36%)** — project / program / portfolio / operations; project life
cycle; phase, phase gate; process groups (Initiating, Planning, Executing, Monitoring &
Controlling, Closing); PMBOK 7's 12 principles + 8 performance domains; predictive /
adaptive / hybrid; stakeholder, sponsor, PMO; charter; business case; assumption log; issue
log; risk register; change control board; lessons learned register; tailoring; EEFs and
OPAs; servant leadership; conflict resolution (collaborate/problem-solve, compromise,
smooth, force, withdraw); communication channels n(n−1)/2; PMI Code of Ethics
(responsibility, respect, fairness, honesty); power/interest grid; RACI.

**D2 · Predictive (17%)** — WBS, WBS dictionary, work package, control account, activity,
milestone list; precedence diagramming (FS, SS, FF, SF), lead, lag; critical path, float
(total, free), crashing vs fast-tracking; Gantt; scope / schedule / cost baselines →
performance measurement baseline; EVM — PV, EV, AC, SV, CV, SPI, CPI, EAC, ETC, VAC,
TCPI; estimating — analogous, parametric, bottom-up, three-point (PERT (O+4M+P)/6);
contingency vs management reserve; procurement — FFP, CPFF, CPIF, T&M, SOW, make-or-buy;
quality tools — Pareto, control chart, cause-and-effect (Ishikawa), histogram, check
sheet, flowchart, scatter diagram; qualitative (probability-impact matrix) vs quantitative
(Monte Carlo, EMV, decision tree) risk analysis; risk responses; Validate Scope vs Control
Quality.

**D3 · Agile (20%)** — Agile Manifesto (4 values, 12 principles); Scrum roles (product
owner, scrum master, developers), events (sprint, sprint planning, daily scrum, sprint
review, sprint retrospective), artifacts (product backlog, sprint backlog, increment);
Kanban — WIP limits, flow, lead time, cycle time, throughput, cumulative flow diagram; XP
(pair programming, TDD, refactoring); Lean (waste, value stream); user story, story
points, planning poker, velocity, burndown / burnup; Definition of Done, Definition of
Ready; MVP; timebox, iteration; backlog refinement; spike; information radiator; servant
leadership; hybrid approaches; self-organising / cross-functional teams.

**D4 · Business Analysis (27%)** — business analyst role vs PM; needs assessment; business
case; elicitation techniques (interviews, facilitated workshops, focus groups, observation,
surveys, document analysis, prototyping, brainstorming); requirement types (business,
stakeholder, solution — functional / non-functional, transition, project, quality);
requirements traceability matrix; requirements management plan; stakeholder analysis;
product roadmap; product backlog; acceptance criteria; verification vs validation; solution
evaluation; MoSCoW; use cases, user stories; process models (context diagram, data-flow,
swimlane); gap analysis; benefits realisation; scope models; interface analysis.

## §4 Calibrated examples (exact shape, ≤50 words)

**Do NOT correct** — house term:
> "The ingest project's soak ends next week." → silence. (`soak` is in §1; the mapping is already known.)

**Correct** — milestone for a work package:
> 📘 PM term: you said **milestone** → PMI says **work package**. Work packages are the lowest Work Breakdown Structure (WBS) level and carry effort; "add the search page" takes days. A milestone is a zero-duration significant point — the page is live. [D2 · Predictive]

**Correct** — risk for an issue:
> 📘 PM term: you said **risk** → PMI says **issue**. The disk filled last night, so it belongs in the issue log with an owner and due date; a risk is an uncertain future event in the risk register with probability and impact. [D1 · Fundamentals]

**Nudge** — D2 idle:
> 📘 Nudge (D2 untouched 16 d): **CPI (Cost Performance Index)** = EV (Earned Value) ÷ AC (Actual Cost) — cost efficiency; below 1.0 means over budget. Its twin **SPI (Schedule Performance Index)** = EV ÷ PV (Planned Value) measures schedule efficiency.
